Training on many GPUs comes down to one question: how do the GPUs combine what they each computed? This page explains the vocabulary in plain words, then lets you try each operation on four GPUs. Read it first, then move on to the other tabs.

1. Why GPUs need to talk

One training step

The model makes predictions on a batch of examples, measures the error (the loss), and computes a gradient: one number per weight saying which way to nudge it. Then every weight is updated.

Data parallelism

Every GPU keeps a full copy of the model and gets a different slice of the batch. Each GPU computes its own gradient from its own slice, so the four gradients are different.

The problem

If each GPU updated with its own gradient, the four copies of the model would drift apart. They must all use the same gradient: the average of the four. Computing that average across GPUs is the communication step.

Why messages

Threads in one program can read the same memory. Separate GPUs and machines cannot: each has its own memory, so data moves only when one side sends a copy and the other receives it. That is called message passing, and MPI is its standard.

3. From all-reduce to the average gradient

  1. Each GPU computes its gradient gk on its own slice of the batch.
  2. An all-reduce with SUM leaves g0 + g1 + g2 + g3 on every GPU.
  3. Dividing by the number of GPUs gives the average. PyTorch DDP does this division for you.
  4. Every GPU applies the same update, so the copies stay identical.

Two classic warm-ups

An all-reduce is the same as a reduce-scatter (each GPU ends up with the total for one chunk) followed by an all-gather (everyone collects all the totals). The ring all-reduce tab does exactly these two phases, one chunk per step.

Worked example. 8 GPUs (p = 8) all-reduce 2 GB of gradients (n = 2 GB) with a ring over NVLink (β = 450 GB/s). Each GPU sends 2 · 7⁄8 · 2 GB = 3.5 GB, so the time is at least 3.5 ⁄ 450 s ≈ 8 ms. The 14 α terms add only about 0.1 ms, because the message is large.

5. Words you will see

rank
The id of one process, usually one GPU: 0, 1, 2, …
world size (p or N)
How many processes take part.
n
Size of the data being combined, in bytes. For gradients: number of parameters × bytes per number (2 for BF16).
α (alpha), latency
Fixed cost of sending any message, a few microseconds. It dominates for small messages.
β (beta), bandwidth
How fast a link moves bytes, in GB/s. It dominates for large messages. Network cards are sold in Gb/s (bits): divide by 8.
NVLink / network
NVLink connects the GPUs inside one machine (fast). Network cards connect machines (slower per card, but each GPU usually has its own).
NCCL
NVIDIA's library that actually runs the collectives on GPUs. PyTorch calls it for you.
bucket
A group of gradients that DDP sends in one all-reduce, so it does not pay α for every weight separately.
overlap, exposed time
Sending gradients while the GPU is still computing. Whatever is left over after computing ends is exposed time: the GPUs just wait.
straggler
A GPU that is slower than the others. Because a collective waits for everyone, one straggler slows the whole step.
